# Java Language Basics

Базовые правила языка, на которых строится всё остальное: типы, передача
аргументов, приведения, массивы, области видимости и доступ. Отсюда же берётся
самый частый вопрос первой пятиминутки — как Java передаёт параметры.

---

## Примитивные и ссылочные типы

```text
примитивные типы
ссылочные типы
```

К примитивам относятся `byte`, `short`, `int`, `long`, `float`, `double`, `char`
и `boolean`. Такая переменная хранит само значение:

```java
int number = 10;
boolean active = true;
char grade = 'A';
```

К ссылочным типам относятся классы, интерфейсы, массивы, `enum`, `record`,
`String` и классы-обёртки. Переменная хранит значение ссылки на объект:

```java
User user = new User();
String text = "Java";
int[] numbers = {1, 2, 3};
```

```text
user
  │
  └────→ User object
```

Несколько переменных могут ссылаться на один объект, и изменение через одну видно
через другую:

```java
User first = new User();
User second = first;
```

```text
first  ──┐
         ↓
      User object
         ↑
second ──┘
```

## Pass-by-value

Java всегда передаёт аргументы **по значению**. Отдельного механизма передачи по
ссылке в языке нет.

Всё различие в том, что именно является значением:

```text
примитив       → копируется само значение
ссылочный тип  → копируется значение ссылки
```

### Передача примитива

```java
public static void change(int value) {
    value = 100;
}

public static void main(String[] args) {
    int number = 10;

    change(number);

    System.out.println(number);   // 10
}
```

В метод передаётся копия значения, изменение параметра на исходную переменную не
влияет.

### Передача ссылки

```java
static class User {

    String name;

    User(String name) {
        this.name = name;
    }
}
```

```java
public static void change(User user) {
    user.name = "Alex";
}
```

Передаётся копия ссылки, но обе ссылки указывают на один объект, поэтому изменение
поля видно снаружи.

А вот переназначение параметра меняет только локальную копию:

```java
public static void change(User user) {
    user = new User("Alex");
}
```

```text
изменили объект через ссылку → результат виден снаружи
переназначили параметр       → снаружи ссылка не меняется
```

### Почему swap не работает

```java
public static void swap(User first, User second) {
    User temp = first;
    first = second;
    second = temp;
}
```

Метод меняет местами только свои локальные копии ссылок. Переменные вызывающего
кода остаются нетронутыми, и классический обмен значениями в Java невозможен.

### Неизменяемые объекты

`String` и обёртки вроде `Integer` неизменяемы, поэтому с ними тот же эффект
выглядит особенно наглядно:

```java
public static void change(String text) {
    text = text + " World";
}
```

Конкатенация создаёт новую строку и присваивает её локальной ссылке. Исходная
переменная указывает на прежний объект.

```java
public static void change(Integer value) {
    value = 100;
}
```

Здесь `value = 100` не меняет существующий объект, а переназначает локальную
ссылку.

С изменяемым объектом всё наоборот:

```java
public static void change(List<Integer> list) {
    list.add(100);
}
```

Метод меняет тот же объект, и изменение видно снаружи.

## Приведение примитивных типов

```text
widening  → расширение
narrowing → сужение
```

Расширение выполняется автоматически:

```java
int number = 10;
long value = number;
```

```text
byte → short → int → long → float → double
char → int → long → float → double
```

Сужение требует явного приведения и может потерять данные:

```java
long value = 3_000_000_000L;
int number = (int) value;
```

`int` не способен представить исходное значение, поэтому результат изменится.

При приведении дробного к целому дробная часть **отбрасывается**, а не
округляется:

```java
double value = 10.9;
int number = (int) value;   // 10
```

```text
10.9  → 10
10.1  → 10
-10.9 → -10
```

Для округления существует `Math.round()`.

### Numeric promotion

В арифметических выражениях `byte`, `short` и `char` автоматически расширяются до
`int`.

```java
byte a = 10;
byte b = 20;

byte c = a + b;   // не компилируется
```

Выражение `a + b` имеет тип `int`, поэтому нужен явный cast:

```java
byte c = (byte) (a + b);
```

Константное выражение компилятор вычисляет заранее, поэтому такой код корректен:

```java
byte value = 10 + 20;
```

Составные операторы присваивания содержат неявное сужающее приведение:

```java
byte number = 10;
number += 20;
```

```text
number += 20  ≈  number = (byte) (number + 20)
```

Компилируется, но от переполнения это не защищает — оно произойдёт молча.

Та же логика действует для инкремента и декремента:

```java
char value = 'A';
value++;

System.out.println(value);   // B
```

При этом `value = value + 1` без приведения не скомпилируется: результат имеет тип
`int`.

## Приведение ссылочных типов

```java
class Animal {}
class Dog extends Animal {}
class Cat extends Animal {}
```

Upcasting — приведение к родительскому типу — безопасен и выполняется
автоматически:

```java
Dog dog = new Dog();
Animal animal = dog;
```

Downcasting требует явного приведения:

```java
Animal animal = new Dog();
Dog dog = (Dog) animal;
```

И проверяется во время выполнения:

```java
Animal animal = new Cat();
Dog dog = (Dog) animal;   // ClassCastException
```

Код скомпилируется, но реальный объект является `Cat`, а не `Dog`.

### instanceof

```java
if (animal instanceof Dog) {
    Dog dog = (Dog) animal;
}
```

С Java 16 доступно сопоставление с образцом, объявляющее переменную сразу:

```java
if (animal instanceof Dog dog) {
    // dog уже имеет тип Dog
}
```

Для `null` проверка всегда возвращает `false`, исключения не возникает, поэтому
отдельная проверка на `null` не нужна.

### Приведение и преобразование

```java
Object value = "Java";
String text = (String) value;      // работает
```

```java
Object value = 10;
String text = (String) value;      // ClassCastException
```

Приведение не превращает произвольный объект в строку. Для строкового
представления существует `String.valueOf(value)`.

```text
cast       → объект уже должен иметь совместимый тип
conversion → создаётся представление значения в другом типе
```

## Массивы

Массив является объектом и относится к ссылочным типам.

```java
int[] numbers = {1, 2, 3};
```

Присваивание копирует ссылку, а не содержимое:

```java
int[] a = {1, 2, 3};
int[] b = a;

b[0] = 100;

System.out.println(a[0]);   // 100
```

То же правило действует при передаче в метод: изменение элементов видно снаружи,
а переназначение параметра — нет.

```java
public static void change(int[] numbers) {
    numbers[0] = 100;              // видно снаружи
}

public static void change(int[] numbers) {
    numbers = new int[]{100, 200}; // не видно снаружи
}
```

### clone

```java
int[] a = {1, 2, 3};
int[] b = a.clone();
```

Для примитивов создаётся отдельный массив со скопированными значениями. Для
объектов копия поверхностная:

```java
User[] a = {new User("Dima")};
User[] b = a.clone();
```

Массивы разные, но ссылки внутри указывают на те же объекты.

```text
array.clone()
→ новый массив
→ shallow copy для ссылочных элементов
```

Двумерный массив в Java — это массив массивов, поэтому `clone()` копирует только
внешний:

```java
int[][] matrix = {
        {1, 2},
        {3, 4}
};

int[][] copy = matrix.clone();   // внутренние массивы остаются общими
```

### Длина и значения по умолчанию

```java
int[] numbers = new int[3];

numbers.length;      // 3
numbers.length = 10; // не компилируется
```

Размер фиксируется при создании; для другого размера создаётся новый массив,
например через `Arrays.copyOf()`.

Элементы инициализируются автоматически:

| Тип элемента | Значение |
|---|---|
| `byte`, `short`, `int`, `long` | `0` |
| `float`, `double` | `0.0` |
| `boolean` | `false` |
| `char` | `'\u0000'` |
| ссылочный тип | `null` |

### Ковариантность

Массивы в Java ковариантны: если `Dog` является `Animal`, то `Dog[]` является
`Animal[]`.

```java
Animal[] animals = new Dog[2];

animals[1] = new Cat();   // ArrayStoreException
```

Компилятор не возражает, но реальный тип массива — `Dog[]`, и ошибка обнаружится
во время выполнения.

```text
массивы  → ковариантны, проверка во время выполнения
generics → инвариантны, проверка при компиляции
```

## Локальные переменные и области видимости

Поля объектов и элементы массивов получают значения по умолчанию, локальные
переменные — нет.

```java
public static void main(String[] args) {
    int number;

    System.out.println(number);   // не компилируется
}
```

Компилятор требует определённого присваивания до первого чтения.

Область видимости ограничена блоком, в котором переменная объявлена:

```java
public static void main(String[] args) {
    int number = 10;

    if (true) {
        int value = 20;
        System.out.println(number);   // доступен
    }

    System.out.println(value);        // не компилируется
}
```

```text
внешний блок   → переменная доступна во вложенных блоках
внутренний блок → переменная снаружи недоступна
```

То же с переменной цикла:

```java
for (int i = 0; i < 3; i++) {
    System.out.println(i);
}

System.out.println(i);   // не компилируется
```

Повторно объявить локальную переменную во вложенном блоке нельзя, пока внешняя
остаётся видимой:

```java
int number = 10;

if (true) {
    int number = 20;   // не компилируется
}
```

Затенять можно только поле класса — параметром или локальной переменной:

```java
class User {

    private String name;

    void setName(String name) {
        this.name = name;
    }
}
```

```text
name      → параметр метода
this.name → поле объекта
```

## Varargs

Позволяет передать переменное количество аргументов одного типа.

```java
public static void print(String... values) {
}
```

Внутри метода параметр имеет тип `String[]`, а компилятор собирает аргументы в
массив на стороне вызова.

```java
print();
print("A");
print("A", "B", "C");
```

Можно передать и готовый массив:

```java
String[] values = {"A", "B"};
print(values);
```

При вызове без аргументов передаётся пустой массив, а не `null`:

```java
public static void print(String... values) {
    System.out.println(values.length);
}

print();   // 0
```

Отдельного внимания требует явная передача `null`:

```java
print((String[]) null);   // values == null
```

Ограничения: varargs-параметр обязан быть последним, и его может быть только
один.

```java
void print(int count, String... values) {}   // корректно

void print(String... values, int count) {}   // ошибка
void test(String... names, int... numbers) {} // ошибка
```

Иначе компилятор не смог бы определить, где заканчиваются переменные аргументы.

## Package, import и уровни доступа

`package` объявляет пространство имён класса и влияет на полное имя типа,
структуру каталогов и видимость package-private членов.

```java
package com.example.service;
```

```text
com.example.service.UserService
```

`import` позволяет использовать короткое имя типа:

```java
import java.util.List;
```

Он не загружает библиотеку во время выполнения и не влияет на размер артефакта —
это разрешение имён компилятором.

```java
import java.util.*;
```

Шаблон охватывает только классы самого пакета: `java.util.concurrent` сюда не
входит, вложенные пакеты импортируются отдельно.

```java
import static java.lang.Math.*;
```

Статический импорт даёт доступ к статическим членам без имени класса:

```java
sqrt(16);
max(10, 20);
PI;
```

Злоупотребление им ухудшает читаемость: непонятно, откуда взялся метод.

### Уровни доступа

```text
private
package-private
protected
public
```

`package-private` получается, когда модификатор не указан.

| Модификатор | Тот же класс | Тот же пакет | Наследник в другом пакете | Любой код |
|---|---:|---:|---:|---:|
| `private` | да | нет | нет | нет |
| package-private | да | да | нет | нет |
| `protected` | да | да | да | нет |
| `public` | да | да | да | да |

Существенная деталь: наследование из другого пакета не даёт доступа к
package-private члену, а `protected` доступен наследнику только через ссылку
своего типа, а не через любой экземпляр родителя.

```java
package com.example.first;

public class Parent {
    protected int value = 10;
}
```

```java
package com.example.second;

public class Child extends Parent {

    public void print() {
        System.out.println(value);
    }
}
```

## Типичные ошибки

### Считать, что Java передаёт объекты по ссылке

Точная формулировка: ссылка передаётся по значению.

### Путать изменение объекта и переназначение ссылки

`user.name = "Alex"` меняет объект, `user = new User("Alex")` — только локальную
ссылку.

### Считать Integer изменяемым

Обёртки неизменяемы, любое присваивание создаёт новый объект.

### Ожидать округление при приведении double к int

Дробная часть отбрасывается: `(int) 10.9` даёт `10`, а не `11`.

### Забывать про numeric promotion

`byte + byte` имеет тип `int`, и присвоить результат обратно в `byte` без
приведения нельзя.

### Полагаться на составное присваивание

`number += 20` компилируется благодаря неявному приведению, но переполнение
произойдёт молча.

### Выполнять downcast без проверки

`(Dog) animal` может дать `ClassCastException`. Реальный тип проверяют через
`instanceof`.

### Путать приведение и преобразование

`(String) value` не превращает произвольный объект в строку — для этого есть
`String.valueOf()`.

### Считать clone массива глубоким копированием

Для массива объектов копируются ссылки, а не сами объекты. То же с внешним
массивом в двумерном.

### Забывать про ковариантность массивов

`Animal[] animals = new Dog[2]` компилируется, а запись `Cat` даёт
`ArrayStoreException` во время выполнения.

### Ожидать значение по умолчанию у локальной переменной

Их получают только поля и элементы массивов.

### Ставить varargs не последним

Компилятор не смог бы определить границу между переменными и обычными
параметрами.

### Считать import подключением библиотеки

Он влияет только на разрешение коротких имён компилятором.

## Краткая памятка

```text
Java всегда pass-by-value

примитив      → копируется значение
ссылочный тип → копируется значение ссылки

изменили объект через ссылку → видно снаружи
переназначили параметр       → снаружи не видно
swap ссылок невозможен
```

```text
widening  → обычно автоматически
narrowing → явный cast, возможна потеря данных
(int) 10.9 → 10, дробная часть отбрасывается

byte / short / char → арифметика через int
b += 5 ≈ b = (byte)(b + 5), переполнение молча
```

```text
Dog → Animal   upcasting, автоматически
Animal → Dog   downcasting, явный cast, ClassCastException
null instanceof X → false
cast ≠ conversion
```

```text
массив — объект с фиксированной length
int[] b = a → копируется ссылка
array.clone() → новый массив, shallow copy для ссылок
двумерный массив → массив массивов, clone копирует внешний

массивы ковариантны → ArrayStoreException
generics инвариантны

поля и элементы массива → default value
локальные переменные    → обязательная инициализация
```

```text
String... values
→ внутри String[]
→ ноль и больше аргументов, пустой массив, а не null
→ только последний параметр, только один
```

```text
private         → только класс
package-private → пакет
protected       → пакет и наследники в других пакетах
public          → отовсюду

package → пространство имён
import  → короткое имя типа, не загрузка библиотеки
import java.util.* не включает java.util.concurrent
import static → статические члены
```

## Краткий ответ для собеседования

Типы в Java делятся на примитивные и ссылочные: первая переменная хранит значение,
вторая — ссылку на объект в куче и может быть `null`.

Аргументы всегда передаются по значению, передачи по ссылке в языке нет. Для
примитивов копируется само значение, для объектов — значение ссылки. Отсюда всё
остальное: через параметр можно изменить состояние объекта, потому что обе ссылки
указывают на один экземпляр, но переназначение параметра меняет только локальную
копию и снаружи не видно. По этой же причине классический swap ссылок написать
нельзя.

Для примитивов расширение выполняется автоматически, сужение требует явного
приведения и может потерять данные, а при приведении дробного к целому дробная
часть отбрасывается, а не округляется. В арифметике `byte`, `short` и `char`
продвигаются до `int`, поэтому сумма двух `byte` не помещается обратно в `byte`
без приведения. Составные операторы и инкремент содержат неявное сужение, из-за
чего переполнение происходит молча.

Для ссылочных типов приведение к родителю безопасно и неявно, приведение к
наследнику проверяется во время выполнения и может дать `ClassCastException` —
поэтому перед ним используют `instanceof`, а с Java 16 сразу с объявлением
переменной.

Массив — объект с фиксированной длиной. Присваивание копирует ссылку, `clone()`
создаёт новый массив, но для ссылочных элементов копия поверхностная. Массивы
ковариантны, в отличие от обобщений, и расплата за это — `ArrayStoreException` во
время выполнения.

Локальные переменные значений по умолчанию не получают и обязаны быть
инициализированы до чтения; их видимость ограничена блоком объявления. Varargs
внутри метода представлен массивом, должен быть последним параметром и при вызове
без аргументов даёт пустой массив.

Наконец, `package` задаёт пространство имён, `import` — лишь удобство записи, а
уровней доступа четыре: `private`, package-private, `protected` и `public`.

## Вопросы на собеседовании

### 1. Чем примитивный тип отличается от ссылочного?

**Ответ:** примитив хранит само значение и имеет фиксированный размер. Ссылочная
переменная хранит ссылку на объект, размещённый в куче, и может быть `null`.

### 2. Что именно хранит ссылочная переменная?

**Ответ:** ссылку на объект, а не сам объект. Это не адрес в привычном смысле:
конкретное представление зависит от реализации JVM, и объект может перемещаться
при сборке мусора.

### 3. Как Java передаёт аргументы в методы?

**Ответ:** всегда по значению. Для примитивов копируется значение, для объектов —
значение ссылки. Поэтому через параметр можно изменить состояние объекта, но
нельзя заставить переменную вызывающего кода указывать на другой объект.

### 4. Что копируется при передаче примитива?

**Ответ:** само значение. Изменения внутри метода на исходную переменную не
влияют.

### 5. Что копируется при передаче объекта?

**Ответ:** ссылка. Обе переменные указывают на один объект, но остаются двумя
независимыми переменными.

### 6. Почему изменение поля объекта внутри метода видно снаружи?

**Ответ:** копия ссылки указывает на тот же объект, поэтому изменение его
состояния видно всем, кто на него ссылается.

### 7. Почему присваивание нового объекта параметру не меняет ссылку снаружи?

**Ответ:** оно меняет только локальную копию ссылки. Исходная переменная
продолжает указывать на прежний объект.

### 8. Почему обычный swap не меняет ссылки снаружи?

**Ответ:** метод меняет местами свои локальные копии. Переменные вызывающего кода
остаются нетронутыми, поэтому классический обмен значениями в Java невозможен.

### 9. Почему String не меняется при конкатенации внутри метода?

**Ответ:** строки неизменяемы. Конкатенация создаёт новый объект и присваивает его
локальной копии ссылки, а исходная переменная указывает на прежнюю строку.

### 10. Почему присваивание нового Integer не меняет исходную переменную?

**Ответ:** по той же причине: обёртки неизменяемы, и операция создаёт новый
объект, меняя только локальную ссылку.

### 11. Чем widening отличается от narrowing?

**Ответ:** расширение идёт к более ёмкому типу и выполняется неявно, без потери
значения. Сужение требует явного приведения и может привести к потере данных.

### 12. Когда требуется явный cast примитива?

**Ответ:** при сужении — например, из `long` в `int` или из `double` в `int`.
Компилятор требует подтвердить намерение, поскольку значение может не поместиться.

### 13. Что происходит с дробной частью при приведении double к int?

**Ответ:** она отбрасывается, а не округляется. Значение 9,99 превращается в 9.
Для округления используется `Math.round()`.

### 14. Почему byte + byte даёт int?

**Ответ:** из-за числового продвижения: операнды меньше `int` перед арифметической
операцией расширяются до `int`. Присвоить результат обратно в `byte` без
приведения нельзя.

### 15. Почему byte += int компилируется?

**Ответ:** составные операторы присваивания содержат неявное сужающее приведение.
Компилятор трактует `b += 5` как `b = (byte)(b + 5)`, поэтому переполнение
произойдёт молча.

### 16. Почему char++ компилируется?

**Ответ:** по той же причине — инкремент включает неявное приведение обратно к
`char`. Значение сдвигается по таблице символов.

### 17. Что такое upcasting?

**Ответ:** приведение ссылки к родительскому типу. Выполняется неявно и всегда
безопасно, поскольку наследник является частным случаем родителя.

### 18. Что такое downcasting?

**Ответ:** приведение к типу наследника. Требует явного указания и проверяется во
время выполнения.

### 19. Когда возникает ClassCastException?

**Ответ:** при попытке привести объект к типу, которым он на самом деле не
является. Компилятор такую ошибку не поймает.

### 20. Для чего используется instanceof?

**Ответ:** для проверки реального типа объекта перед приведением. С Java 16
поддерживает сопоставление с образцом, объявляя переменную сразу:
`if (o instanceof User user)`.

### 21. Что возвращает null instanceof SomeType?

**Ответ:** `false` для любого типа. Отдельная проверка на `null` перед
`instanceof` не нужна.

### 22. Чем приведение отличается от преобразования значения?

**Ответ:** приведение ссылочного типа меняет только точку зрения на объект, сам
объект остаётся прежним. Приведение примитива создаёт новое значение, возможно с
потерей данных.

### 23. Что происходит при `int[] b = a`?

**Ответ:** копируется ссылка на массив, а не его содержимое. Обе переменные
указывают на один массив, и изменения видны через обе.

### 24. Чем clone() массива отличается от присваивания?

**Ответ:** `clone()` создаёт новый массив и копирует в него элементы. Присваивание
лишь копирует ссылку.

### 25. Почему clone() массива объектов является поверхностной копией?

**Ответ:** копируются ссылки на элементы, а не сами объекты. Оба массива указывают
на одни и те же экземпляры, поэтому изменение состояния объекта видно через любой
из них.

### 26. Как устроен двумерный массив в Java?

**Ответ:** это массив ссылок на массивы. Строки могут иметь разную длину, а
`clone()` копирует только внешний массив.

### 27. Можно ли изменить array.length?

**Ответ:** нет, поле неизменяемо, и длина фиксируется при создании. Для
изменяемого размера существует `ArrayList`.

### 28. Какие значения по умолчанию получают элементы массива?

**Ответ:** нули для числовых типов, `false` для `boolean`, `\u0000` для `char` и
`null` для ссылочных. Массив всегда инициализируется при создании.

### 29. Почему локальная переменная без инициализации не компилируется?

**Ответ:** локальные переменные лежат в стеке и значений по умолчанию не получают.
Компилятор требует определённого присваивания до первого использования — это
защита от чтения мусора.

### 30. Что такое ковариантность массивов?

**Ответ:** `String[]` считается подтипом `Object[]`. Массивы, в отличие от
обобщений, ковариантны, что позволяет передавать их в методы с более общим типом
элемента.

### 31. Когда возникает ArrayStoreException?

**Ответ:** при попытке записать в массив элемент несовместимого типа. Это обратная
сторона ковариантности: через ссылку `Object[]` можно попытаться положить в
`String[]` число, и ошибка обнаружится только во время выполнения.

### 32. Что такое область видимости?

**Ответ:** часть программы, в которой переменная видна. Обычно ограничена блоком,
где она объявлена.

### 33. Почему переменная из if недоступна после блока?

**Ответ:** её область видимости ограничена телом блока, и после выхода переменная
перестаёт существовать.

### 34. Можно ли повторно объявить локальную переменную во вложенном блоке?

**Ответ:** нет, переменная внешнего блока остаётся видимой, и объявление с тем же
именем будет ошибкой. Затенять можно только поле класса.

### 35. Что означает `String... values`?

**Ответ:** переменное число аргументов. Вызывающий передаёт произвольное
количество строк, включая ноль.

### 36. Как varargs представлен внутри метода?

**Ответ:** обычным массивом. Компилятор собирает переданные аргументы в массив на
стороне вызова.

### 37. Что получит метод при вызове без аргументов?

**Ответ:** пустой массив, а не `null`. Отдельного внимания требует явная передача
`null`: он будет истолкован как сам массив.

### 38. Почему varargs должен быть последним?

**Ответ:** иначе компилятор не смог бы определить, где заканчиваются переменные
аргументы и начинаются остальные параметры.

### 39. Что делает package?

**Ответ:** объявляет пространство имён для класса. Влияет на полное имя типа, на
структуру каталогов и на видимость package-private членов.

### 40. Что делает import?

**Ответ:** позволяет использовать короткое имя класса вместо полного. На загрузку
классов и на размер артефакта не влияет.

### 41. Импортирует ли java.util.* подпакет java.util.concurrent?

**Ответ:** нет. Шаблон охватывает только классы самого пакета, вложенные пакеты
нужно импортировать отдельно.

### 42. Что делает import static?

**Ответ:** позволяет обращаться к статическим членам без имени класса, например
писать `max(a, b)` вместо `Math.max(a, b)`. Злоупотребление ухудшает читаемость.

### 43. Какие четыре уровня доступа есть в Java?

**Ответ:** `private`, package-private без модификатора, `protected` и `public`.

### 44. Чем protected отличается от package-private?

**Ответ:** package-private виден только внутри своего пакета. `protected`
дополнительно доступен наследникам из других пакетов — но лишь через ссылку своего
типа, а не любого экземпляра родителя.

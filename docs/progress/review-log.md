# Журнал повторений

Здесь фиксируются прогоны блоков по вопросам и то, что не получилось ответить.

Смысл файла простой: сорока с лишним конспектов слишком много, чтобы держать их
в голове целиком. Повторять нужно не всё подряд, а то, где вы уже спотыкались.

## Как вести

После прогона блока по вопросам — запись с датой, номерами проваленных вопросов
и датой следующего повтора.

```text
провалил сегодня    → повторить через неделю
провалил повторно   → повторить через три дня
ответил дважды      → вопрос закрыт, из журнала убирается
```

Формулировка «провалил» означает не «не вспомнил слово», а «не смог связно
объяснить вслух». Узнавание и воспроизведение — разные вещи, и на собеседовании
нужно второе.

Отметка `[x]` в [`topic-tracker.md`](topic-tracker.md) ставится, когда по блоку
не осталось открытых записей в этом журнале.

## Формат записи

```markdown
## 2026-01-15, блок 11

Провалил:

- `hibernate/03` вопросы 7, 12 — проксирование и equals для сущностей
- `spring/05` вопрос 19 — REQUIRES_NEW и отдельное соединение

Повторить: 2026-01-22
```

Короткое пояснение после номера обязательно: через неделю номер сам по себе
ничего не напомнит.
